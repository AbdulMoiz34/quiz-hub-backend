# Quiz Hub Backend

Simple Express.js + MongoDB Atlas modular monolith, based on the readability of the Rakhshinda Art backend. **One `src/app.js` entry point**, small controllers, models, routes, validations, middleware and helpers. No Redis or extra dependencies.

## Status

1. Backend foundation, single seeded admin: implemented.
2. Admin quiz and question management: implemented.
3. Six-slot scheduling: implemented.
4. **Student attempt start and recovery**: implemented in this PR.
5. **NOT YET BUILT**: answer autosave, final submission, anti-cheat log persistence, grading, admin result pagination, browser integration, deployment and 250-user load test.

This backend is **not safe for a live exam yet**.

## Setup

Install Node.js 22+ and `npm install`. Copy `.env.example` to `.env`. Fill in a MongoDB Atlas URI, exact `CORS_ORIGINS`, a random `JWT_SECRET`, and admin credentials. Rotate previously leaked database credentials; never commit any secrets.

```sh
npm run db:check
npm run db:seed
npm run dev
npm run check
npm test
```

Commit the `package-lock.json` generated by npm before production releases.

## Admin APIs

- `POST /api/v1/admin/auth/login`, `GET /api/v1/admin/auth/me`, `POST /api/v1/admin/auth/logout`
- `GET, POST /api/v1/admin/quizzes`, `GET, PUT /api/v1/admin/quizzes/:id`, `PATCH /api/v1/admin/quizzes/:id/publish`
- `GET /api/v1/admin/slots?quizId=...`, `POST /api/v1/admin/slots`, `PATCH /api/v1/admin/slots/:id`

## Student APIs (no account or login)

- `GET /api/v1/student/quizzes` — available quiz metadata only (active, non-full slots).
- `POST /api/v1/student/attempts/start` — start or safely retry an attempt.
- `GET /api/v1/student/attempts/current` — return only this attempt's information and safe questions.

Start request (send a new UUIDv4 for a new attempt, reuse the **same UUID** for retries):

```json
{
  "quizId": "507f1f77bcf86cd799439011",
  "studentName": "Ahmed Ali",
  "rollNo": "00123",
  "startKey": "e72b4dd0-3ab3-49eb-bec8-b55c5015938c"
}
```

**Roll numbers accept only digits 0-9** (1-25 chars); they remain **strings** so `00123` stays `00123`. No preloaded student roster or signup. Student name may be freely entered.

On the frontend, generate `startKey` using `crypto.randomUUID()` and **persist it before calling** the start API (for example in localStorage scoped to that quiz and roll number). Keep the same value on network retries. Do not share the key with another student. The backend hashes it before storage, and returns a separate HttpOnly signed exam-session cookie (6 hours).

A student cannot begin until a quiz is published and a slot is actively open. Each roll number is allowed **one attempt per quiz across all slots** (unique MongoDB index). Slot admission count is incremented atomically in the **same MongoDB transaction** as attempt creation, and the effective deadline is the earlier of the slot closing time and quiz duration. A refresh with the existing cookie returns the same private question order, with **no answer keys or hidden test cases**.

Important trade-offs:
- Any name + roll number is allowed, so **student impersonation / someone claiming a roll number first cannot be prevented**. The session key only protects the attempt *after* creation.
- If a student clears both cookies and local storage or switches devices, recovery is not possible without an administrator reset (to be implemented later).
- MongoDB Atlas Free transaction support and performance must be verified against the **actual** cluster; burst writes to the same slot can be slow under 250 concurrent starts.
- Autosave and final submission are not included in this PR, so **no answer durability is promised yet**.
- Browsers must send `credentials: "include"` for the exam-session cookie and use allowed `Origin` headers for POST. For Vercel/AWS on separate sites, configure HTTPS and cross-site cookie policy later.
